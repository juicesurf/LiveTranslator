# LiveTranslator

原生 macOS Live Captions 英文字幕 → Apple Translation 繁體中文。字幕只留在記憶體，不上傳第三方、不使用 API Key，不執行 AppleScript、OCR 或螢幕擷取。

## 進度

Phase 1 技術原型及 Phase 2 完整句子翻譯已實作。Phase 3 已加入 NSPanel 浮動視窗與基本顯示設定；Phase 4 已提供逐句經過時間、TXT／Markdown 匯出與未儲存提醒（依需求不另做逐字稿視窗）。真實字幕、離線模型與翻譯品質仍需實機驗證。

已檢查環境：macOS 26.5.2、Xcode 26.6、Swift 6.3.3、macOS 26.5 SDK。部署目標 macOS 26.0。

## 開啟與驗證

以 Xcode 開啟 `LiveTranslator.xcodeproj`，選擇 LiveTranslator／My Mac 執行。

```sh
xcodebuild -project LiveTranslator.xcodeproj -scheme LiveTranslator -configuration Debug -derivedDataPath build build
swift test --scratch-path build/swift-tests
```

成品：`build/Build/Products/Debug/LiveTranslator.app`。目前使用 ad-hoc 簽署，重編譯後若權限失效，需完全結束 App，在系統設定 → 隱私權與安全性 → 輔助使用移除舊 LiveTranslator，再用 + 加入上述 App 並開啟權限。Terminal 的權限不能代替 App 的權限。不更改系統安全設定。

1. 開啟 macOS Live Captions、設定英文、播放英文內容。
2. 在 App 授予輔助使用權限，按「開始／重新連線」。背景每 500ms 讀取 AX，依系統執行檔路徑尋找程序，不固定 PID 或本地化視窗名稱。
3. 按「準備模型／重試翻譯」，接受 Apple 模型下載提示。也可先停止擷取，再按「測試英翻繁中」驗證固定句子。
4. 英文未完成時應顯示「等待完整句子」；出現句尾後才翻譯。不論等待多久、文字多長，都不強制切段。
5. 查看「上次排程等待／模型翻譯耗時」。下載與模型忙碌會增加延遲，不保證固定秒數內顯示中文。
6. 關閉再開啟 Live Captions，確認等待與自動恢復。模型下載完成後斷網，驗證離線翻譯。

AX 診斷只在畫面及記憶體中顯示。只在字幕 AXScrollArea 中讀取第一個有效 AXStaticText，不再串接整個程序的所有靜態文字；依 Value、Title、Description 選第一個非空屬性。此選擇依本機已驗證的單一字幕節點階層，仍須實機核對來源與屬性映射。

## 字幕排列

每個句子以英文在上、對應中文在下顯示；英文較小且使用次要顏色，中文較大。未翻譯或未完成的句子有獨立等待提示，使用原生 NSScrollView 追蹤實際捲動位置。位於底部時更新後自動捲至最新項目；手動往上捲時暫停跟隨，捲回底部（容許 4pt 誤差）恢復。內容更新期間保留目前 offset，不把排版變動誤判為使用者捲動。不啟用 App 或搶鍵盤焦點。字幕列表使用確定高度的非延遲排版，避免離屏估計高度因新字幕加入而改變。

## 完整句子翻譯

- 只在 `. ? !` 句尾提交；支援句尾引號與右括號。小數內的點不切句，常見稱謂、e.g.、i.e.、姓名首字母及縮寫採保守規則。
- 沒有字數／時間觸發的暫時翻譯。標點已出現的句子立即進入單一序列翻譯迴圈；未完成尾句只顯示英文。
- 使用滾動 snapshot 重疊還原內容；相同 snapshot 不重送。相同文字的不同出現位置仍為獨立句子。
- 句子修正後只重送改變的句子；前句增刪單字時，後句未變的翻譯可繼續使用。舊的非同步結果須符合目前句子身分與完整原文才接受，不能覆蓋修正後的句子。
- `TranslationService` 可替換；en → zh-Hant，明確檢查不支援狀況，重用 SwiftUI 管理的 session。macOS 26.4 以上使用 lowLatency，較舊系統使用預設策略。

英文分句有歧義：例如 U.S. 或姓名首字母在段尾可能同時代表句尾，目前保守等待後續明確句尾；省略號也不視為完整句。規則不是完整英文語法解析器。沒有空格分隔的連續英文句子尚未特別處理。完全相同的整個 snapshot 無法判斷講者是否再次說了同樣內容；完全沒有重疊的大幅修正可能被當成新段落。這些限制仍須以真實講座資料驗證。

## 測試

Swift Testing 涵蓋增量與重複 snapshot、字幕捲動、真正重複句、修正增刪單字、標點新增／撤回、縮寫、小數、引號、長文字及長時間等待不觸發翻譯、舊結果拒絕、已完成句只翻一次、後句未變不重譯，以及停止／重試狀態。

系統權限、下載介面、低延遲模式品質與實際翻譯速度、離線能力仍屬手動驗證項目。尚未實作 Real-time／Sentence 切換設定；目前固定完整句子模式。

## 儲存中英字幕

按工具列「儲存」選擇 TXT 或 Markdown，選擇路徑後以 UTF-8 寫入。匯出按下按鈕時本次全部字幕（含捲動上方內容），每句包含經過時間、完成狀態、英文及對應中文。一般儲存期間仍會擷取字幕；晚於匯出快照的新字幕或修正仍視為未儲存。取消不寫入檔案，未主動儲存不永久保存。

捲動手動驗證：擷取到超過視窗高度後往上捲，持續新增／翻譯字幕時不應被拉回底部；再捲到底部，應恢復跟隨。仍需在實際滑鼠／觸控板操作下確認。

原生捲動回歸測試涵蓋往上捲後連續增加內容時 offset 不變，以及回底部後新增內容繼續跟隨；19 個測試通過。此測試操作真實 NSScrollView／NSClipView，尚未涵蓋完整視窗中的實際滑鼠及觸控板事件。

## Phase 3 浮動視窗

啟動後顯示獨立 NSPanel，預設置頂與深色。可拖曳標題列、拖動邊緣縮放，並記住視窗位置／大小。右上角圖釘切換置頂，「文字大小」按鈕提供英文字體 12–30pt、中文字體 16–42pt、55–100% 不透明度、系統／深色／淺色及僅中文顯示。這些閱讀設定目前只在本次 App 執行期間保留。

頂部提供開始／停止、儲存、清除。有未儲存內容時，清除會先詢問是否儲存，且清除後繼續擷取；未改變的舊 snapshot 不會再次出現在清除後的字幕中。右上角「更多操作」保留權限、模型準備／重試、測試句與診斷。關閉字幕視窗會停止擷取；點 Dock 圖示或選單「檔案 → 顯示字幕視窗」（⌘0）可重開。

NSPanel 使用 nonactivatingPanel、hidesOnDeactivate=false、becomesKeyOnlyIfNeeded=true。只有啟動／使用者明確重開時才呼叫 orderFrontRegardless；字幕與翻譯更新不呼叫 activate、makeKey 或 orderFront。視窗仍可在使用者操作文字選取及系統儲存介面時取得必要鍵盤輸入。

手動驗收：

1. 先儲存需要的字幕，⌘Q 結束舊版，再開啟新 App；重編譯後權限失效時移除舊權限項目並重加。
2. 開始擷取並準備模型，在其他 App 持續打字，確認字幕持續更新且不轉移鍵盤焦點。
3. 測試置頂開關、拖曳與縮放、字體／透明度／外觀／僅中文，並確認上捲後仍保留閱讀位置。
4. 測試清除、儲存及關閉重開；清除後舊翻譯不應回填。
5. 全螢幕與多桌面使用 fullScreenAuxiliary／canJoinAllSpaces，實際表現仍需在使用者的桌面配置驗證。

單元測試可驗證原生面板旗標、設定不主動顯示／變成 key，以及清除後拒絕舊結果；無法代替真實輸入焦點、多螢幕、全螢幕與系統下載／儲存面板的互動驗證。

## 重複字幕修正

使用者提供的逐字稿顯示整段重複與「已暫停」控制文字混入。已縮小 AX 讀取範圍；同時將前後 snapshot 的逐字精確重疊比對改為忽略大小寫／邊界標點的比對，並在字幕捲動伴隨少量 ASR 改字或插字時採用有界編輯對齊。這只比對相鄰 snapshot，不全域刪除相同句子。對齊最多處理前一 snapshot 的末 400 個單字與新 snapshot 前 420 個單字，無可靠重疊時仍視為新內容。

26 個測試通過，新增捲動時改字／插字／標點變更、講座片段重疊及真正再次重複說話的案例。逐字稿不包含原始 snapshot 時序，不能證明所有真實來源變化均已涵蓋；仍需以新 App 重新擷取驗證。舊記憶體中已累積的重複紀錄不會自動修復。

## 字幕自動換行

字幕 hosting view 先以捲軸可用寬度限制 SwiftUI 排版，再依完整換行高度更新文件大小。英中字幕均無行數上限；調整視窗寬度時重新計算高度，長句不做截斷。新增實際 NSHostingView 排版測試，驗證 700pt 縮至 300pt 時英中長句內容高度增加、恢復寬度後高度還原。27 個測試通過；仍需實際視窗縮放與捲動操作驗收。

## Phase 4 時間與未儲存保護

不新增獨立逐字稿視窗。每句在首次出現時記錄 timestamp，修正與翻譯完成不改時間；介面和匯出顯示相對本次首次開始擷取的 HH:MM:SS（不是影片播放時間）。停止／重開同一 session 不歸零，經過時間包含停止期間；清除字幕後重新計時。固定測試句若在開始擷取前輸入，會從該測試句首次出現開始計時。

狀態分為英文未完成、待翻譯、已翻譯、翻譯失敗。TXT 與 Markdown 均保持英中逐句穿插；Markdown 會跳脫字幕中的格式字元，避免字幕被解讀成文件標記。

有尚未匯出的字幕／修正／翻譯時，清除或 ⌘Q 提供「儲存並繼續／不儲存／取消」。儲存使用最近選擇的格式（預設 TXT）。提醒與後續儲存期間暫停字幕及翻譯結果寫入；取消或失敗時保留資料並恢復更新。這可避免匯出後、清除／結束前又進來新內容而未儲存。關閉浮動視窗只停止擷取，字幕仍留在記憶體，不等於結束 App。

驗證：Debug build 成功；32 個測試通過，包括時間身分、匯出排序／格式、Markdown 跳脫、儲存快照與後續修改、保護期間拒絕更新。系統對話框仍需手動測試：

1. 儲存 TXT、Markdown，檢查時間及英中對照；取消選檔不應更改未儲存狀態。
2. 儲存後新增字幕或等翻譯完成，再按 ⌘Q，應再次提醒。
3. 清除／結束時選取消，字幕應保留並恢復更新；選儲存後取消選檔，亦不應清除或結束。
4. 選不儲存才直接清除／結束；寫檔錯誤時應保留字幕並顯示錯誤。
